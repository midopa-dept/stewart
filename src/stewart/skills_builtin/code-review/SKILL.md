# 코드 리뷰

## 차례
1. 범위를 정한다: `git diff`(또는 주어진 가지·커밋)로 바뀐 파일 목록과 크기를 본다.
2. 파일마다 읽는다 — 바뀐 줄만이 아니라 그 함수 전체와 부르는 곳(search 로 찾기).
3. 볼 것(중요한 것부터):
   - 정확성: 빈 값·0·음수·큰 입력·예외 길, 경계, 동시성, 자원 닫기
   - 보안: 바깥 입력을 명령·경로·SQL 에 바로 넣는지, 비밀이 기록에 남는지
   - 호환: 바꾼 함수의 다른 호출자, 설정·파일 꼴 변화
   - 시험: 바뀐 동작을 붙잡는 시험이 있는지, 없으면 무엇을 시험해야 하는지
4. 확인할 수 있는 것은 돌려 본다(시험·작은 재현). 확인 못 한 지적은 "의심"이라고 적는다.

## 보고 꼴
- 지적마다: 파일:줄 / 무엇이 문제인가 / 어떤 입력에서 무엇이 틀어지나 / 고칠 안 — 심각한 것부터.
- 문제없으면 그렇다고 한 줄. 취향 문제는 따로 묶거나 뺀다.
