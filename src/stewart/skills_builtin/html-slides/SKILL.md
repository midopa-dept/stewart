# HTML 발표자료 만들기

파일 하나짜리 HTML 발표자료를 만든다. 브라우저만 있으면 열리고, 인쇄하면 한 장이 한 쪽이 된다.
바탕 틀은 딸린 파일 `base.html` 에 있다(load_skill 의 file 로 읽는다). 새 자료는 이것을 작업 폴더에 복사해서 시작한다.

## 먼저 정할 것(모르면 한 번에 묻는다)
1. 쓰임: 말하며 넘기는 발표인가, 나눠 주고 읽는 자료인가. 밀도가 여기서 갈린다.
2. 분량: 대략 몇 장인가. 내용(글·메모·원본 파일)이 있으면 받는다.
3. 분위기: 아래 스타일 중 하나를 권하고, 사람이 다른 것을 원하면 따른다.

## 무대(바꾸지 않는 규칙)
- 모든 장은 1920×1080 고정 무대 안에 그린다. 무대를 창 크기에 맞춰 통째로 늘이고 줄이며, 남는 곳은 가장자리 색으로 둔다.
- 폰·작은 창이라고 내용을 다시 배치하지 않는다. 장 안의 크기는 1920×1080 기준 px 로 적는다.
- 장 바꾸기는 `.active` 와 `visibility`·`opacity` 로 한다. `display:none` 은 쓰지 않는다(숨은 장의 크기를 잴 수 없어 검사가 틀린다).
- 색·글꼴은 `:root` 변수로만 둔다. 장마다 색을 따로 박지 않는다.
- `prefers-reduced-motion` 이면 움직임을 끈다. 움직임은 장이 바뀔 때 흐려졌다 나타나는 정도면 충분하다.

## 밀도
- 말하는 발표: 한 장에 1–3줄. 큰 글자, 생각 하나, 여백을 넉넉히.
- 읽는 자료: 한 장에 4–8줄(또는 카드 4–6개). 표·도식·짧은 설명을 쓴다.
- 넘치면 글자를 줄이지 말고 장을 나눈다. 본문 글자는 1920 기준 28px 아래로 내리지 않는다.
- 한 줄은 대략 40자(말하는 발표)·55자(읽는 자료)를 넘기지 않는다.

## 조작·쪽 번호·인쇄
- 화살표·Space(Shift+Space 는 뒤로)·PageUp·PageDown·Home·End 로 넘긴다.
- 주소 끝 `#n` 으로 n번째 장을 바로 연다. 넘길 때 해시도 바꾼다.
- 장마다 아래에 `n / 전체` 쪽 번호를 보인다(스크립트가 채운다).
- 인쇄: `@page` 를 1920×1080 으로 두고, 인쇄 때는 모든 장을 보이게 해서 장마다 쪽을 나눈다. 배경색이 찍히게 `print-color-adjust: exact` 를 둔다.

## 파일 하나, 바깥 주소 없음
- CSS·JS·그림을 모두 파일 안에 넣는다. `http(s)://` 로 시작하는 글꼴·스크립트·그림·CDN 을 쓰지 않는다. 망이 없는 곳에서도 그대로 열려야 한다.
- 그림·도식은 인라인 SVG 로 그린다. 글자 색은 `currentColor`, 강조는 `var(--accent)` 로 맞춘다.
- 사진처럼 꼭 필요한 그림은 사람이 준 파일을 base64 data URI 로 넣는다. 크면(수 MB) 미리 알린다.

## 글꼴
- 기본은 시스템 글꼴 줄: `"Malgun Gothic", "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`. 운영체제마다 있는 것이 잡힌다.
- 사람이 글꼴 파일(.ttf·.otf)을 주면, 자료에 쓰인 글자만 잘라 넣을 수 있다. fonttools 가 있을 때만 된다.
  ```bash
  python3 -c "import fontTools" && echo 있음        # 없으면 이 길은 건너뛰고 시스템 글꼴로 둔다
  # 1) 자료의 글자를 모은다(태그 빼고, 겹친 글자 빼고) → chars.txt
  # 2) 쓰인 글자만 남긴다(woff2 는 brotli 가 더 필요하니 woff 로)
  pyftsubset 글꼴.otf --text-file=chars.txt --flavor=woff --output-file=sub.woff
  # 3) base64 로 바꿔 @font-face 의 src: url(data:font/woff;base64,…) 에 넣는다
  ```
- 글자를 고친 뒤에는 잘라 넣기를 다시 한다(새 글자가 빠지면 그 글자만 다른 글꼴로 보인다).
- 글꼴의 라이선스가 넣어 퍼뜨리기를 허락하는지 사람에게 확인한다.

## 몇 해 지난 브라우저에서도(오래된 Chromium 계열 기준)
- 쓰지 않는다: `dvh`·`svh`, `:has()`, 컨테이너 쿼리(`@container`), CSS 중첩, `@layer`, `color-mix()`, `Array.prototype.at`, `structuredClone`.
- 스크립트는 `var`·`function`·`forEach` 정도로 쓴다. 모듈(`type="module"`)·빌드 도구는 쓰지 않는다.
- 고른 기능이 몇 해 전 브라우저에도 있었는지 모르면 쓰지 않는다.

## 스타일(하나를 골라 끝까지 같은 체계로)
- 종이: 밝은 미색 바탕, 짙은 먹색 글, 강조색 하나. 교육·보고에 무난하다(`base.html` 의 기본값).
- 어두운 무대: 짙은 바탕, 밝은 글, 강조색 하나. 큰 화면 발표·시연에 맞다.
- 격자: 흰 바탕에 가는 세로 격자선, 굵은 제목, 왼쪽 맞춤. 숫자·표가 많은 자료에 맞다.
- 장마다 모양을 바꾸지 않는다. 표지·구역 표지·본문·마무리 정도만 꼴을 나눈다.
- 장 위에 "스타일 A"·"미리보기"·파일 이름 같은 작업용 글을 쓰지 않는다.

## 만든 뒤 검사
- 브라우저(예: playwright 의 chromium)가 있으면: 1920×1080 으로 열어 장마다 `#n` 으로 넘기며 잰다.
  - 넘침: 장 안 요소의 아래·오른쪽 끝이 장(1920×1080)이나 쪽 번호 줄을 넘는가, `scrollHeight > clientHeight` 인 칸이 있는가.
  - 겹침: 같은 장의 글 상자끼리 사각형이 겹치는가(일부러 겹친 장식은 빼고).
  - 키로 넘기기·`#n` 열기·인쇄(PDF 쪽 수 = 장 수)를 한 번씩 본다. 1280×720 과 폰 크기에서 무대가 16:9 로 남는지 본다.
- 브라우저나 셸이 없으면(대화 자리 등): 장마다 줄 수(밀도 상한)와 한 줄 글자 수 상한을 세어 넘는 장을 나눈다. 그리고 "화면으로는 보지 않았다"고 보고에 적는다.
- 파일 안에 `http://`·`https://` 가 없는지, 위의 옛 브라우저 금지 목록이 없는지 찾아본다.
