# 보안 리뷰(바뀐 것)

## 범위
- 기본은 지금 바뀐 것(`git diff`, 또는 주어진 가지·커밋). 저장소 전체 감사는 사람이 그렇게 말할 때만.

## 볼 것
1. 바깥 입력이 닿는 곳: 셸 명령·SQL·경로·템플릿·정규식·역직렬화(pickle·yaml.load)에 그대로 들어가는가.
2. 인증·권한: 검사를 빼먹은 길, 권한 확인 전 동작, 기본값이 열림인가.
3. 비밀: 키·토큰이 코드·로그·오류 메시지·기록 파일에 남는가, 기본 비밀번호.
4. 네트워크: 서버 쪽 요청 위조(사설 주소로 가는 요청), 인증서 검사 끔, 리다이렉트 따라가기.
5. 파일: 경로 거슬러 오르기(`..`), 링크 따라가기, 임시 파일 권한·이름 예측.
6. 의존성: 새로 더한 꾸러미의 출처·판 고정.

## 확인
- 의심 지점마다 실제로 닿는 입력 길을 따라가 본다(search 로 호출자 찾기). 가능하면 작은 재현(가짜 입력)으로 확인한다.
- 확인 못 한 것은 "의심"으로 표시한다. 고칠 때 다른 동작을 바꾸지 않는지 시험을 돌린다.

## 보고 꼴
- 심각도(높음·중간·낮음) / 파일:줄 / 어떤 입력이 무엇을 하게 되나 / 고칠 안. 높음부터.
- 공격 방법을 길게 설명하지 않는다 — 고치는 데 필요한 만큼만.
