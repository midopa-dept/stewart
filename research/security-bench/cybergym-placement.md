## 확인한 사실(CyberGym README, github.com/sunblaze-ucb/cybergym, Apache-2.0 — 하위 WebFetch 요약)
- 구성: 에이전트는 **컨테이너** 안에서, PoC 제출 서버(cybergym.server)는 **호스트**에서. 서버는 "에이전트 컨테이너와 호스트에서만" 닿으면 된다. 제출은 submit.sh → SQLite, 끝나고 scripts/verify_agent_result.py 로 검증.
- 크기: 과제 자료 약 240 GB(HF git LFS), 바이너리 전용 서버 자료 약 130 GB(컴파일 환경 없음), 전체 서버 자료 약 10 TB(컴파일 환경 Docker 이미지). 부분집합 내려받기 스크립트(download_subset.py)는 있으나 크기 표기 없음.
- 공식 10과제 부분집합: arvo:47101·3938·24993·1065·10400·368, oss-fuzz:42535201·42535468·370689421·385167047(쉬운 5 + 어려운 5).
- 망 격리: `python3 -m cybergym.firewall start` → 인터넷 직접 경로 없는 cybergym-internal 망 + 허용 목록 Squid 프록시(나가는 것만 거름, 들어오는 것은 안 막음). README: "Deploy everything locally. Do not expose any part of CyberGym to the public internet."
- README 에 CPU 아키텍처·특권 모드·하드웨어 권장은 없다(미확인). 과제가 OSS-Fuzz/ARVO 리눅스 바이너리라 **x86_64 를 전제로 본다(추정)**.
- 빌린 GPU: 일반(Docker) 인스턴스는 Docker-in-Docker 불가, **VM 인스턴스**는 systemd·Docker 가능(대여처 문서, 검색 요약). VM 은 SSH 키 등록이 필요하고 공급 수가 적다(미확인).

## 설계 원칙
모델 서빙과 채점 환경을 떼어 놓는다. 모델은 지금 평가 장비(Docker 인스턴스, vLLM)가 그대로 서빙하고, 에이전트 실행기 + CyberGym 과제 컨테이너 + 제출 서버는 Docker 가 되는 x86_64 기계 한 곳에 둔다. 자료(≥370 GB)는 한 번 받아 오래 두는 곳이 싸다.

## 후보 비교
| | A. 로컬 장비(격리 VM) | B. 빌린 GPU VM 인스턴스(GPU+Docker 한 기계) | C. 빌린 CPU VM(채점만) + 지금 평가 장비(모델) | D. 로컬 개발 맥 |
|---|---|---|---|---|
| Docker | 설치·운영 여부 **미확인**(사람 확인) | VM 이라 가능(문서) | 가능 | 다른 일과 같이 쓰는 VM |
| 아키텍처 | **미확인**(x86_64 이어야 함) | x86_64 | x86_64 | **arm64**(uname) → x86 바이너리 에뮬레이션, 크래시 판정이 달라질 위험 |
| 디스크 | 큰 디스크(자료 약 370 GB + 과제 이미지가 들어감) | 대여마다 ≥500 GB 디스크 요금 + 매번 받기 | 같음(매번 받기) | 자료가 안 들어감 |
| 받기 시간 | 1회(로컬 회선, 미확인 속도) | 대여마다 약 370 GB(1 Gbps 면 약 50분+, GPU 요금 흐르는 중) | 대여마다(CPU 요금) | — |
| 모델 연결 | 로컬 장비 → 빌린 GPU 의 vLLM 포트. 지금 망 허용 규칙에 vLLM 포트 허용 추가 필요(사람·관리 설정) | 같은 기계 localhost | CPU VM → 평가 장비(망 허용 규칙 새로) | 지금 평가와 같음 |
| 망 격리 | 다른 서비스와 같은 기계 → **별도 VM 또는 rootless Docker + cybergym-internal + 호스트 방화벽**으로 로컬 망 막기 필요 | 빌린 기계라 로컬 망과 분리(가장 깨끗) | 분리 | 개발 맥의 정책 샌드박스와 충돌 |
| 비용(어림) | 전기만. 모델 장비 시간만 듦 | GPU 요금 + 받기 시간 + 큰 디스크 | CPU VM 요금(작음) + 받기 + 평가 장비 | — |
| 위험 | 취약 바이너리를 로컬 장비에서 돌림(크래시 PoC 실행) — 격리가 핵심 | VM 공급·SSH 키 등록(사람) | 두 기계 조율 | — |
| 판정 | **권고(조건부)**: 사람이 x86_64·Docker·자원·격리 VM 가능 여부를 확인하면 | 대안: 파일럿 1회용 | 차선 | **제외**(arm64, 디스크 부족, 공용 VM, 샌드박스) |

- 바이너리 전용(130 GB)에서 에이전트가 컴파일하지 못할 때 점수가 원 논문·카드 수치와 비교 가능한지 **미확인** — 파일럿에서 원 논문 설정(level1, 컴파일 환경 유무)을 FAQ 로 먼저 확인.

## 사람이 확인할 것(결정 전)
1. 로컬 장비: CPU 아키텍처·코어·RAM, Docker(또는 VM 하이퍼바이저) 유무, 남는 디스크 공간, 다른 서비스와 격리할 VM 을 띄울 수 있는지
2. 망 허용 규칙: 로컬 장비 → 빌린 GPU 의 vLLM 포트 허용을 더할지
3. 로컬 회선으로 약 370 GB 받기 허용
