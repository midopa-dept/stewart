## 0. 한 쪽 결론

1. 보고서가 짚은 **빈 곳 여섯은 지금 main(판 75)에도 그대로 비어 있다**[확인]. 오늘 들어간 것(웹·doc_search·압축 2단·되짚기·사람 손 카드·스킬·이미지·Anthropic·대화 여럿)은 여섯 가운데 어느 것도 메우지 않았다. 넷(재시도·본문 툴콜 파싱·인자 복구·편집 되먹임)은 돈 없이 가짜 서버 시험으로 바로 할 수 있다.
2. 보고서의 **평가 지적(만든 쪽이 짠 벤치, 봉인 세트, 동료 기준선, 공개 벤치)은 우리가 이미 반쯤 가고 있는 길**이다: 보류 묶음 h1.x, 사전 등록 P-001, 공개 벤치 팔 X1-05(SWE-bench Verified sub200·Terminal-Bench 2.1, mini-SWE-agent·Terminus 기준선) 계획·부분집합까지 있다[확인]. 보고서는 이것을 모른다(공개 저장소에 없다). 다만 어댑터 코드는 아직 없고, 동료 실행기 선택이 다르다(보고서 OpenCode·Pi ↔ 우리 mini-SWE-agent·Terminus·Claude Code).
3. 보고서의 **세 축 방법론(격차를 μ·α·β·ε 로 쪼개 엔진·모델 프로필·스킬에 옮김)은 새 것**이고 우리 쪽에 대응물이 없다. P-001(양자화·abl·실행기 판 대비)과 주제가 다르다. 새 등록으로 세울지 사람 결정이 필요하다.
4. 우리 측정과 어긋나는 곳은 크지 않다. 가장 큰 것: 보고서는 "추론을 되돌려 보내지 않아 `preserve_thinking` 효과 없음"을 바로 고칠 결함으로 보지만, 우리 27B 는 되돌려 보내지 않는 지금도 생각 켬 80.6–86.8% ↔ 끔 52–75% 로 크게 갈린다[총괄 전달·E16 표 확인]. 되돌려 보내기는 "결함 고침"이 아니라 "손잡이로 넣고 잴 것"이 맞다.

## 4. 보고서와 우리 측정이 어긋나는 곳

1. **추론 되돌려 보내기(가-5)**: 보고서는 "긴 실행과 생각 켠 모델의 전제 조건"으로 본다. 우리 27B 는 되돌려 보내지 않는 지금도 생각 켬이 크게 낫다 — E16 같은 32과제에서 켬 129/160(80.6%) ↔ 끔 84/160(52.5%)[확인 Claude 대 27B 비교 계획 표(비공개 운영 기록)], 총괄 전달 범위는 켬 80.6–86.8%·끔 52–75%. 되돌려 보내면 문맥이 빨리 차고(보고서 나-3 도 인정) Qwen 템플릿에서 툴콜이 깨진 사례도 있다. → 전제 조건이 아니라 실험 대상.
2. **"어디서나 지는 일반 결함(μ)"이 클 것이라는 암묵 가정**: 같은 Sonnet/Opus 에서 stewart 실행기가 Claude Code 와 성공률이 비슷하고 비용이 30–50% 적다(표본 작음)[총괄 전달 — 원 보고 대조 안 함]. 강한 모델에서는 실행기가 뒤지지 않는다는 뜻이라, 격차가 있다면 모델 성분(α, 27B 급에서만 지는 것)에 몰려 있을 가능성이 높다 [추정]. 보고서의 축 분해와는 맞지만, "동료가 stewart 를 이기는 칸이 없으면 신호가 없다"는 보고서의 위험 항목이 실제로 일어날 수 있다.
3. **문맥 관리 서술**: 보고서 "창의 0.7 을 넘으면 줄임"은 평가 길 기본만 맞다. 실사용(chat·허브)은 오늘부터 가리기 0.5 → 요약 0.7 이고, 굴러가는 가리기(M=10)는 손잡이로만 있다(prefix 캐시 때문에 기본으로 안 고름 — 압축 조사, 비공개 운영 기록).
4. **"기존 벤치 = 만든 쪽이 짠 것뿐"**: 보류 묶음 h1.x·사전 등록·공개 벤치 팔·mini-SWE-agent 기준선 계획을 보고서는 모른다. 다만 h1.x 도 우리 쪽 제작이라 보고서의 "출제자 편향" 지적 자체는 남는다.
5. **동료 실행기·벤치 판**: 보고서 OpenCode·Pi(+OpenHands 예비), Terminal-Bench 2.1 + 공개 벤치 둘셋 합쳐 200–300문제. 우리 등록 초안 mini-SWE-agent v2·Terminus(OpenHands·Aider 는 "이번엔 넣지 않음"), SWE-V sub200 + TB 2.1. 보고서는 SWE-bench Verified 의 오염 문제(우리 계획서가 적은 것)를 다루지 않는다.
6. **모델 축**: 보고서 Qwen 계열 27B(판 이름 가림)·Gemma 4 31B·셋째 미정, 원본 가중치 우선·abl 은 나중. 우리 P-001 은 같은 27B 의 orig·abl·abl-b(W4A16) 대비이고 오늘 Claude 비교 칸은 abl-int8h 다. 모델 "계열" 축은 우리 쪽에 아직 없다.
7. **돈 단가**: 보고서 3090 한 장 $0.22–0.50/h·한 장 시간당 10–40회 가정. 우리 실측은 4×3090 장비 $1.176/h, 회차분당 $0.00218(v2 생각 켬 회차 ≈ 5.44 회차분)[확인 연구 예산표(비공개 운영 기록)]. 2×2×2 어림은 우리 단가로 다시 셀 수 있다 — 이번엔 안 셈.
8. **x86 서버**: 보고서 "로컬 x86 장비는 동시 5개, CPU 클라우드 수백 달러(미확인)". 우리 계획은 "Docker 되는 VM 형 GPU 장비 한 대에서 서빙과 과제 컨테이너를 같이"(공개 벤치 팔 계획 §4, 비공개 운영 기록) — 값은 도구 담당 답 대기 [모름].
