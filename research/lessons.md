# 시행착오 장부 — 연구 쪽

> 원래 기록: 총괄이 고쳐 쓰는 시행착오 장부(비공개 운영 기록, 2026-11-12 – 11-15). 사람(제품 주인)의 지시(11-12)로 시작했다. 연구 쪽 항목만 옮겼고, 옮긴 항목의 숫자·이력·안 좋은 일은 그대로 두었다.
> 꼴: 장부 · 서술(판정 없음). 줄마다 나오는 측정 자체의 꼴은 그 측정의 문서를 따른다.
> 실행 조건: 해당 없음(장부). 줄에 나오는 실행 모델은 Qwen 계열 27B 4비트(사전 시험은 로컬 맥의 9B), 장비는 빌린 GPU(주로 RTX 3090 4장·8장 기계)다.

**맨 위 요약**
- 같은 과오를 되풀이하지 않으려고 적는 장부다. 새 일이 생기면 그날 안에 한 줄을 더한다. 하위 담당은 자기 과오를 보고에 적고, 총괄이 여기로 옮긴다.
- 한 줄의 꼴: **무슨 일** / 까닭 / 무엇이 잡았나 / 다시 안 나게 한 것 / 상태. 돈·시간이 든 것은 금액을 적는다.
- 이 공개판은 원래 장부의 연구 쪽 항목만 옮겼다: 항목 58개("잘 돌아간 것" 5개 포함)와 "되풀이된 꼴" 5개. 한 항목에 다른 일이 섞인 곳은 연구 쪽 문장만 남겼다.
- 가장 자주 되풀이된 꼴은 셋이다.
  - 돈 드는 측정을 "이 측정이 답을 가를 수 있나"를 보기 전에 걸었다(검정력·천장·물음 글·손잡이가 걸리는 값인지).
  - 시각을 짐작으로 적었다(규칙을 세운 뒤에도 네 번).
  - 점검·대조가 헛통과를 냈다.
- 옛 낭비 사건(11-09 – 11-12 오전)은 [money/cost-by-experiment.md](money/cost-by-experiment.md) 3절(낭비 사건 W1–W11)에 표로 있다.

## 되풀이된 꼴(먼저 읽을 것)

1. **확인하지 않고 "된다"고 말했다.** 결과를 확인하기 전에 다음 걸음으로 갔고, "평가 쪽은 캐시를 지우지 않는다"고 말했다(아래 11-12 측정·평가의 evalq 줄). → 실제 응답·실물 실행을 본 뒤 말한다. 못 본 것은 "미확인"이라 적는다.
2. **시험이 통과해도 실사용은 다르다.** 시험 1,200개·평가 80%대인 판이 실사용에서 "알아봐"에 폴더를 뒤졌다. 세션 안(샌드박스)에서 못 재는 것은 사람 셸 한 줄로 실물을 잰다. 실사용 실패는 고치기 전에 장면으로 적는다(실사용 회귀 묶음, 판 121 예정).
3. **점검 도구 자체가 거짓 통과를 낸다.** run-code-check 6/9(아무것도 안 돌았는데 "막힘" 통과), 학습 gate 가 통과 0 인데 채택 가능, 분석 스크립트가 도는 회차를 끝난 것으로 셈. → 양성 대조가 먼저다. 기준이 못 서면 "판정 불가".
4. **우리 과제로 잰 것을 일반 결론처럼 전했다.** 창 1 "기능을 쌓을수록 내려간다"를 증거 종류를 앞세우지 않고 전함 → 사람이 짚음. → 증거의 종류(개발 과제/봉인/공개/실사용)와 기제 유무를 붙여 말한다([trust-frame.md](trust-frame.md)).
5. **어림이 번번이 낮았다.** 창 1 어림 $4.3 → 실제 $6.67(배수 1.55), 끝 시각 17:50 → 20:10. → 어림에 실측 배수를 곱하고, 8시간 상한까지의 여유를 시작 조건으로 박는다. 중요한 칸을 앞에 둔다.

## 2026-11-12

### 측정·평가
- **로컬 맥 9B 사전 시험이 본 대여 전 결함 둘을 잡았다**(잘한 것 — 계속할 것): 요청 idle 60초가 비스트리밍 걸음을 모두 자름, 평가기가 내장 스킬을 격리 위반으로 셈. 그대로 빌렸으면 창 1 이 크게 망가졌다. → 돈 드는 실행 전에 돈 안 드는 자리에서 전 구간을 돈다.
- **창 1 어림이 1.55배 빗나감**($4.3 → $6.67, 3.5h → 6.24h). / 무거운 칸(L4·L5)의 회차 시간을 낮게 봄, 차선이 놀았음(running 평균 4.0·2.0·1.67·0.5, waiting 0 — 장당 동시 2 로 묶인 과제, 조각 꼬리) / 중간 보고의 배수 / 조각을 넷으로 나눠 차선을 채움, 시작 조건에 배수.
- **병목을 두 번 헛짚음**: 로컬 맥 의심(실제 맥 몫 9–17%) → 시간 내역 표가 틀림(도는 회차를 끝난 것으로 셈, "생각이 가장 크다"는 오전달) → 실측으로 "차선별 동시 회차 부족". / 추정을 사실처럼 전함 / 연구 담당이 스스로 바로잡음.
- **evalq 가 공용 uv 캐시를 지웠다**(mini 회차가 child_env 의 공용 캐시를 물려받고 끝날 때 rmtree — 평가 대기열 도구의 한 설치 판부터). 다른 점검의 오프라인 환경 짓기가 실패. / 회차 캐시를 stewart 회차에만 줌 / 그 점검을 맡은 담당이 실패를 넘기지 않고 알림 / 평가 대기열 도구를 고친 판. 평가 결과에는 영향 없었음(확인).
- **evalq 한계 둘이 "빠른 길"을 막는다**: 대기열을 한 번에 하나만 돎(장비를 여러 대 빌려도 병렬 불가), 대기열당 차례 20개 상한. / 처음 설계의 범위 / 창 2 를 짜다 드러남 / **미해결 — 공개 벤치 계획의 첫 고침.**
- **여러 장비에 한 대기열을 걸면 칸이 장비에 고르게 안 나뉜다.** X1 에서 같은 칸의 장비 차이가 84 대 43. → 비교할 칸은 한 장비 안에서.
- **8시간 상한에 걸려 실험을 날린 일**(11-12 새벽 민감도 28회 중 1회) → 시작 조건 "어림 × 배수 + 0.5h ≤ 6.5h", 중요한 칸을 앞에.
- **창 1 결과의 증거 수준**: 우리 과제 73개 × 1회, v1 천장, 한 과제 = 3.1pt, stewart 를 만들며 같이 만든 과제. → 공개 벤치로 다시 확인(사람 결정), 기본값을 바꿀 때 요구할 증거를 결정의 무게로 나눔.

## 11-12 밤 — 공개 벤치를 넓게 돌리던 때(총괄 적음)
- **로컬 맥 메모리 압박을 평가 회차 탓으로 짚음**(free 59MB 를 보고 Q2 를 줄이려 함) / 재지 않고 짐작 / 사람이 친 ps 로 잡힘: 73개 5,038MiB 중 Claude 앱·세션이 약 4.5GiB, 회차는 다 합쳐 수백 MiB, 진짜 압박은 색인 짓기 같은 GB 급 준비 일 / "누른다" 싶으면 프로세스별로 먼저 잰다. 상한 24→32 는 로컬 설정 고침 뒤.

- **사람 손을 여러 번 빌리고, 빌린 장비를 이어 쓰지 않음** / 사람: "너희가 알아서 빨리, 장비는 계속 이어 써라" / 사람에게는 칠 한 줄·승인·결과만, 장비는 다음 대기열을 이어 건다.
- **"등급 기본값을 실측대로 넣고 보고"를 사람의 권장 승인으로 읽음** / 사람: 서브에이전트 여럿 검토 + 보고서 뒤 결정 / 방향 결정은 "맡긴다"는 말이 분명할 때만 위임으로 읽는다.
- **판정 실패 꼴을 diff 를 열지 않고 "능력 차이"로 읽음**(연구 담당, 11-13 등급 초안 §4 — 비공개 운영 기록) — 지킴 실패 152 를 "보호 시험 고침"·"L01 진짜 실패"로 썼으나 실제는 시험 더하기가 거의 다(단언 바꿈 2), L01 은 새 파일 → 검토 2 가 뒤집음 / 연구 담당 / 판정 실패를 해석하기 전에 실패 회차의 실제 변경(diff)을 전수 또는 표본으로 열어 꼴을 나눈다.
- **73과제 벽시계 중앙값으로 칸 속도를 견줌**(연구 담당, 창 2 고르기 규칙) — 중앙값은 천장 v1 쪽이 정하고 칸은 시간 블록으로 돌아 교란이 섞임, "4096 재시도 3배"도 timeout 두 회차 탓 / 연구 담당 / 속도 비교는 과제 짝 비(기하 평균)와 어려운 부분만 값을 함께, 합·비율은 timeout 회차를 빼고도 낸다.
- **문서 시각을 또 짐작으로 적음**(연구 담당, 11-13 아침) — 09:2x–09:49 에 쓴 덧붙임 다섯에 "10:0x·10:1x·10:2x·09:5x"를 적었다. 실제보다 늦은 시각이다. "시각은 date 로" 기억 규칙을 두고도 세 번째다 / 연구 담당 / 시각을 적는 줄을 쓰기 직전에 `date` 를 같은 명령 안에서 찍고, 그 값을 붙여 넣는다(쓴 뒤 grep 으로 "x" 시각을 훑음).
