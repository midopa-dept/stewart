## 2. D1 — 무인 실행 기본 기능 수준(미리 적은 규칙)
- 점추정 최고 B = **L1(뼈대)**. 규칙("B 보다 3pt 안인 가장 낮은 단")으로 **L* = L1** 이다.
- B 대비 차이(과제 군집 95% CI):
  - L2 −2.7 [−8.2, +2.7]
  - L3 −4.1 [−11.0, +1.4]
  - L4 −5.5 [−12.3, 0.0]
  - L5 −5.5 [−13.7, +2.7]
- 읽기
  - **기능을 쌓을수록 통과율이 조금씩 내려간다(89.0 → 86.3 → 84.9 → 83.6 → 83.6).** 사람의 걱정("덕지덕지 붙으면 오히려 저하")과 같은 방향이다.
  - 다만 하나하나는 CI 가 0 을 품는다. L4 는 상한이 0.0 으로 경계다. "해친다"고 확정하지는 않는다. "**더해서 얻은 것이 보이지 않는다**"까지는 말할 수 있다.
  - **시간은 분명히 나빠진다.** 자기 점검(L4)은 회차 중앙값이 75s → 225s(3배)다. 기억·스킬(L5)은 198s 다. 생각·걸음이 늘어서다. 같은 통과율에 3배 시간이다.
  - **stewart 모든 단이 mini(L0)보다 낫다**: L1 +17.8 [+8.2, +28.8] … L5 +12.3 [+2.7, +23.3]. CI 하한이 모두 0 위다. 27B 에서는 "bash 하나"보다 stewart 의 뼈대가 낫고, 그 위의 덧붙임이 이득을 더하지 못한다.
- L1 이 L2 와 다른 것은 도구 다섯(glob·todo_write·shell_output·ask_user·delegate)과 끝내기 전 확인이다.
  - v1 에서는 확인 명령이 "시험 없음"이라 확인이 돌지 않는다. 그래서 L1↔L2 차이는 v2 에서만 뜻이 있다(78.1 대 75.0, 한 과제 차이).
  - L1 에 ask_user 가 없어도 ask-missing 범주는 통과했다(최종 답으로 물음). ask-conflict·irreversible 은 L1·L2 모두 0 이다.
- **연구 담당 권고(개발 결정은 총괄·개발 담당)**: 무인 실행(code 프로필) 기본을 L1·L2 쪽으로 가볍게 두고, 자기 점검 넷(L4)은 기본으로 켜지 않는다.
  - L1 과 L2 사이는 가를 수 없다. 그러니 시간이 가장 짧은 L2(지금 평가 기본)를 그대로 두는 것도 규칙 안이다. 규칙상 고른 단은 L1 이다.
  - 실사용 기본(L5 근처)에 대해: 기억·스킬이 이 개발 과제에서 이득을 내지 못하고 시간을 2–3배 쓴다. 대화 길 칸(창 2)을 보고 함께 정하자.
