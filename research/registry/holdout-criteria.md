# 평가 과제 공개/숨김 나누기 기준(연구 담당 제안, 2026-11-09) — 공개 작업·평가 담당용

> 원래 기록: 연구 담당의 봉인(보류) 묶음 기준과 개정 1–4(2026-11-09–11-10). 숫자·규칙·개정 이력은 그대로 옮겼다.
> 꼴: 규칙(결과 전). 개정 4 는 결과를 본 뒤 바꾼 기준이며, 그 사실을 아래 "결과를 본 뒤 기준을 바꾼 점 밝히기"에 적었다.
> 봉인 묶음 장부는 [holdout-sets.tsv](holdout-sets.tsv)다.

과제 본문은 이 문서에 없다(ID·범주·지표만). v2.0.2 32과제: R 12(feature 4·rename 3·trace 5) · G 4(regress) · L 6 · Q 8(act 4·ask 4) · V 2.

## 두 목표
- 오염 방지: 논문 주장에 쓰는 점수는 공개 웹·모델 학습·**우리 실행기 개선 선택**에 쓰이지 않은 과제에서 낸다.
- 재현성: 남이 같은 평가기로 우리 숫자의 일부를 다시 낼 수 있어야 한다.

## 기준
1. **세 묶음**: 공개(dev) — 논문과 함께 과제·채점기 공개, 실행기 개선 선택에 써도 됨 / 숨김(held-out) — 비공개, 논문 확증 주장에만 / 새 보류(fresh) — 아직 아무 실행기 선택에도 안 쓰인 새 과제(P-001 §7 의 확증용).
2. **이미 실행기 선택에 쓴 v2 32과제는 "숨김" 이 될 수 없다**(fix1·생각 켬을 이 과제로 골랐다 = 적응적 과적합). 따라서 v2.0.2 32과제는 전부 **공개 후보**, 숨김·새 보류는 새로 만든다. 단 공개 시점은 논문 제출 때(그 전엔 비공개 유지 — 다른 담당의 개선 작업이 내용을 보지 않게).
3. **층화**: 숨김·새 보류는 v2 의 범주 비율(R·G·L·Q·V, Q 는 act/ask 반반)을 따르고, 공개 세트와 기준선(b480fe7 또는 등록 시 기준) 성공률 평균이 ±5pt 안이 되게 맞춘다(난이도 맞춤).
4. **크기**: 숨김 + 새 보류 합 ≥ 32(v2 와 같은 크기). 32 미만이면 상호작용 CI 가 ±16pt 를 넘어 확증 주장이 안 된다(P-001 §6).
5. **보고서 누출 규칙**: 숨김 과제는 보고서·인계 문서·노트에 ID 밖의 내용(파일명·명령·정답 단서)을 쓰지 않는다. 이미 보고서에 내용이 나온 과제(예: 명령 문자열이 인용된 Q02)는 숨김 불가.
6. **해시 약속**: 숨김 묶음은 만들 때 sha256 을 운영 기록과 이 registry 에 적고(내용은 비공개), 논문에 그 해시를 실어 "사후 제작 아님" 을 보인다.
7. **카나리**: 공개 과제 파일마다 카나리 문자열을 넣어 학습 데이터 오염을 나중에 검사할 수 있게 한다.
8. **은퇴·순환**: 숨김 과제는 확증 실험 3회(또는 개선 결정 1회라도)에 쓰이면 공개로 은퇴하고 새로 채운다. 사용 횟수를 registry 에 센다.
9. **출처**: 공개 저장소·공개 CVE 를 바탕으로 한 과제는 모델이 외웠을 수 있어 공개 쪽으로, 처음부터 쓴 저장소 과제를 숨김 쪽으로 우선 배정.
10. **채점기 공개**: 숨김 과제의 채점기 코드 공통부는 공개하고 과제별 숨긴 시험만 비공개.

## 개정 2 (2026-11-10, 총괄 11/10 06:0x 요청 — 외부 에이전트 기준선 실행을 어떻게 셀지, 제안)
- **"기준선 실행"** = 우리 실행기·기법과 무관한 외부 에이전트(예: Claude Code 사다리)를 보류 묶음에 돌려 서술용 기준선만 얻는 실행. 기법 선택·개선 결정에 쓰지 않는다.
- 셈: holdout-sets.tsv 에 `uses_baseline` 칸을 따로 둔다. 기준선 실행은 uses_confirmatory 로 세지 않고, 은퇴(§8) 계산에도 넣지 않는다. 단 같은 묶음에 외부 기준선은 **에이전트·모델 판마다 1회**(회차 수는 그 실행 안에서 정함)까지.
- **노출 기록(중요)**: 외부 API 에이전트를 돌리면 보류 과제 본문이 공급사로 나간다. 실행 날짜·공급사·모델 ID·전송 범위를 note 에 적고, 그 뒤로 이 묶음은 "외부 노출됨" 으로 표시한다. 노출 묶음은 우리 모델·실행기의 확증에는 계속 쓰되(우리 모델은 그 공급사 학습과 무관), **노출 뒤 그 공급사의 새 모델 판 확증·기준선에는 쓰지 않는다**(학습 오염 가능 — 공급사의 데이터 사용 정책은 연구 담당이 확인하지 않았다).
- 순서 권고: h1.0 은 맞춤 → P-001 확증 → P-002 확증을 먼저 끝내고, 외부 기준선(12월)은 그 뒤. 외부 기준선을 먼저 돌려도 우리 확증에는 지장이 없으나, 노출 기록이 확증 전에 남으면 해석이 번거롭다.
- **확정(총괄 결정, 2026-11-10 06:0x)**: 위 개정 2 를 제안 그대로 확정. 공급사 데이터 사용 정책은 확인하지 못한 것으로 두고 보수적으로 적용한다.

## 개정 3 (2026-11-10 12:1x, 총괄)
- **보류 묶음의 정체 = 과제 sha**: 과제 정의 sha 목록(과제마다 정의 파일 sha)의 sha256. 실행 판 sha(run_eval --hash — 채점기·격리 코드 포함)는 따로 적는 칸이다. 실행 판이 바뀌어도 과제 sha 가 같으면 **같은 묶음**(사용 횟수·노출 기록을 이어 센다). 과제 sha 가 바뀌면 새 묶음(새 줄).
- holdout-sets.tsv: `task_sha`(정체) 칸을 더하고, 지금까지의 `sha256` 칸은 `run_sha`(그 줄을 만들 때의 실행 판)로 이름을 바꾼다. h1.x 의 task_sha 는 평가 담당이 준다.
- **유효 조건**: 확증·보류 묶음 실행은 회차 기록에 `meta.agent_fence`(모델 실행을 좁은 울타리 안에서 띄웠다는 표시)가 있어야 유효하다. 없으면 그 실행은 무효(사용 횟수에도 안 셈). 예외는 해당 등록의 개정으로 미리 적은 경우만(P-001 개정 4 의 X1-01 조건).
- 배경(총괄 전달): A4 에서 mini-SWE-agent 가 작업 폴더를 몰라 디스크를 뒤져 평가기 과제 파일을 읽었다(그 회차 무효, 쓰기 0, h1.x 안 파일 열린 것 0). 지난 실행 4,253회차(stewart·Claude)는 평가기 폴더를 연 흔적 0.

## 개정 4 (2026-11-10, 사람 채택 — 총괄 전달. 아래는 연구 담당 초안(비공개 운영 기록)의 글 그대로)

## 바꾸는 글귀
- §3 "공개 세트와 기준선(b480fe7 또는 등록 시 기준) 성공률 평균이 ±5pt 안이 되게 맞춘다(난이도 맞춤)" → 아래 "맞춤 기준(개정 4)" 으로 바꾼다. 개정 1(맞춤 실행은 사용 아님)은 그대로.

## 맞춤 기준(개정 4)
1. 실행: 기준선 커밋 하나(b480fe7)로 보류 묶음 6회(3회 두 번도 됨). 공개 묶음 기준선 값은 이미 있는 3회 값을 쓴다.
2. 전체: 보류 − 공개 기준선의 전체 성공률 차이가 **±10pt 안**. (근거: 6회 대 3회의 회차 흔들림만으로 95% 반폭 ±7.9pt — 참 난이도가 같아도 ±5pt 밖일 확률 0.21, ±10pt 밖 0.01.)
3. 범주: 범주마다 바닥·천장이 아님 — 6회 합 성공률이 0% 도 100% 도 아님. 단 공개 기준선에서도 0% 또는 100% 인 범주는 검사에서 뺀다. 범주별 차이는 기록만 하고 판정에 쓰지 않는다(과제 2–12개라 반폭 ±13–32pt).
4. 판정은 6회를 합쳐 한 번만. 밖이면 회차를 더 돌리지 않고, 걸린 범주만 바꾼 새 판(h1.x+1)을 만든다.
5. 까닭: 확증 대비(P-001 H2·H3, P-002)는 모두 같은 보류 묶음 안의 칸 사이 차이라 묶음 전체 난이도가 몇 pt 다른 것은 대비를 치우치게 하지 않는다. 맞춤이 막아야 하는 것은 대비의 여지를 없애는 바닥·천장(h1.0 의 L 0/18 같은 것)이다.

## 결과를 본 뒤 기준을 바꾼 점 밝히기(문서·논문에 넣을 문단)
보류 묶음의 난이도 맞춤 기준은 처음에 "기준선 3회 평균 ±5pt" 였다. h1.0(−5.2pt)과 h1.1(3회 +7.3pt, 6회 +7.8pt)이 이 기준 밖으로 나온 뒤, 기준이 회차 흔들림보다 좁다는 계산(6회 대 3회 95% 반폭 ±7.9pt)을 근거로 기준을 "전체 ±10pt + 범주 바닥·천장 없음, 6회 한 번 판정" 으로 바꿨다. 이 변경은 결과를 본 뒤의 것이므로 옛 기준의 판정(밖)과 새 기준의 판정을 함께 적는다. h1.1 의 과제는 맞춤 결과를 보고 고치지 않았다. 맞춤 실행은 기준선 커밋 하나만 돌린 것이고, 확증 칸(모델·기법 비교)의 데이터는 이 변경 전에 하나도 보지 않았다. 계산식과 값은 사전 등록 장부에 남긴다.
