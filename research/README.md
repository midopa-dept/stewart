# stewart 연구 기록

stewart(작은 로컬 모델로 도는 에이전트 실행기)를 고치면서 잰 것을 그대로 공개하는 곳입니다. 잘 나온 결과만이 아니라, 확증하지 못한 결과, 결과를 본 뒤 고친 셈, 장비 고장과 놀린 돈도 같이 적습니다.

**맨 위 요약**
- 모든 결과에는 **꼴 꼬리표**가 붙습니다. 탐색·서술(판정 없음)인지, 결과 전에 적은 규칙으로 한 번 잰 **확증**인지 구별합니다. 확증이 아닌 숫자로 "올랐다·나아졌다"를 말하지 않습니다.
- 각 측정에는 결과 전에 적은 규칙과, 그때 고정한 스크립트·묶음의 sha256 이 붙습니다. 결과를 본 뒤 바꾼 것은 그렇다고 적습니다.
- 숫자는 원래 기록에서 다시 계산하지 않고 옮겼습니다.
- 지금 들어 있는 것: 개발·봉인 규약, "어디까지 믿나" 틀, 창 3(moderato 생각 깊이) 한 벌, 창 4(presto 생각 깊이 — 확증 못 함), 돈(낭비 표·실험별 지출·장비 장부), 사전 등록 P-001–P-003 과 실험 장부, 분석 스크립트, 평가기·과제 묶음 해시, 개발 실측(창 1·창 2·등급 재측정 설계), 공개 벤치 계획·조사와 BrowseComp-Plus 확증 A, 선행 연구(T1–T5), 보안 벤치 준비, 조사 둘, 개선 계획과 자기 개선 조사, 시행착오 장부의 연구 쪽, 등급 연구의 선행 연구.

## 공개 범위와 빼는 것
- **공개합니다:** 계획, 사전 등록, 결과 전 고정 sha, 결과(안 좋은 것 포함), 판정 규칙과 그것이 바뀐 이력, 신뢰 틀, 돈과 장비 시간.
- **빼거나 바꿔 적습니다**
  - 서빙한 모델의 정확한 판 이름과 어댑터 이름은 적지 않습니다. "Qwen 계열 27B, 4비트" 수준으로만 적습니다.
  - 장비 대여처의 이름은 적지 않습니다. 사양·시간·돈은 적습니다.
  - 봉인 묶음의 문항 원문은 적지 않습니다. 묶음이 있다는 사실, 문항 수, sha, 결과는 적습니다.
  - 집 인프라, 세션 이름, 기계 경로는 적지 않습니다. 원래 기록에 있던 내부 파일 이름은 이 폴더 안 경로로 바꾸거나 "비공개 운영 기록"으로 적습니다.
  - 논문 원고는 학회 규정을 확인할 때까지 넣지 않습니다.

## 꼬리표와 낱말
| 꼬리표 | 뜻 |
|---|---|
| 개발 점검 · 서술 | 문항별 기록을 읽고 고쳐도 되는 개발 묶음에서 잰 값입니다. 판정이 없고, "그럴 수도 있다"까지만 말합니다 |
| 거르기 | 결과 전에 적은 "명백히 나쁜 후보를 버리는 체"입니다. 걸리지 않았다는 것은 나쁘지 않다는 증거가 아닙니다 |
| 확증 | 봉인 묶음에서, 결과 전에 적은 규칙과 고정한 스크립트로 **한 번** 잰 값입니다. 실패하면 "효과 없음"이고 그 묶음은 그 물음에 다시 쓰지 않습니다 |
| [확인] · [추정] · [모름] · [어림] | 기록·코드로 본 것, 어림, 모르는 것입니다 |

- **개발 묶음 / 봉인 묶음**: 개발 묶음은 문항을 읽고 설계를 고쳐도 됩니다. 봉인 묶음은 아무도 문항별 기록을 읽지 않고 집계만 봅니다. 자세한 것은 [protocol.md](protocol.md)입니다.
- **우리 과제**: 개발 실측 과제 v1·v2(코딩·대화 쓰임새, 모두 개발 묶음)입니다. **h1·h2** 는 우리 과제의 봉인 묶음입니다. h1 은 지난 실험들에서 닳았고, h2 는 아직 쓰지 않았습니다.
- **통과(pass_v2) · 기능 · 지킴**: 우리 과제의 통과는 숨긴 시험이 통과하고(기능), 건드리면 안 되는 파일을 건드리지 않았을 때(지킴)입니다. pass_v2 는 새 채점기, 옛 success 는 옛 채점기 판정이고 늘 나란히 적습니다.
- **등급**: stewart 의 일하는 방식 이름입니다. presto(빠르게), moderato(보통), largo(깊게), rubato(바깥 유료 모델)입니다.

## 실행 조건 칸
각 문서 맨 위의 "실행 조건" 칸이 모델·엔진 판·장비를 적습니다. 공개판에서 원래 기록과 달라진 칸은 여기뿐입니다(모델 판 이름 → 계열·크기·정밀도, 대여처 → "빌린 GPU").

## 역할 이름
측정은 여러 Claude Code 세션과 사람이 나눠 맡았습니다. 공개판에서는 역할로 적습니다.
| 역할 | 하는 일 |
|---|---|
| 사람(제품 주인) | 제품 기본값·돈·봉인 쓰기를 정합니다 |
| 총괄 | 순서를 정하고 장비를 빌리고 돌려줍니다 |
| 연구 담당 | 설계·결과 전 규칙·보고서를 씁니다. 봉인 문항별 기록을 보지 않습니다 |
| 평가 담당 | 장비에서 실행하고, 고정한 스크립트로 집계를 냅니다 |
| 개발 담당 | stewart 판을 냅니다 |
| 도구 담당 | 평가기·서빙 도구와 장비 묶음을 만듭니다 |
| 장비 설정 담당 · 로컬 장비 담당 | 로컬 장비의 권한·설정과 시험 VM 을 맡습니다(설계는 비공개 운영 기록) |
| 검토 | 결과를 읽고 반론하는 독립 서브에이전트(통계·과최적화·제품)입니다 |
