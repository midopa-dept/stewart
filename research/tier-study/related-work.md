# 등급 연구 — 선행 연구: 무엇이 있고 무엇이 없나

> 원래 기록: 비공개 운영 기록(2026-11-15 15:5x, 총괄)의 1절을 옮김.
> 꼴: 문헌 조사(판정 없음). 측정 결과가 아니다.
> 실행 조건: 해당 없음(웹 조사). 우리 모델은 Qwen 계열 27B 4비트.
> 공개판에서 바꾼 것: "못 찾음"을 "우리 조사 범위에서 못 찾음"으로 적었다(없다는 증명이 아니다). 우리 개발 점검의 내부 칸 이름을 풀어 적었다. 출처 표시는 원문 그대로 지켰다.

**맨 위 요약**
- 사람의 물음(2026-11-15): 이런 연구·계측을 27B 모델에서 해 놓은 사례가 있나, 더 큰 모델에 같은 교훈을 적용한 사례는 있나.
- 27B 안팎에서, 우리가 재려는 것(도구 수·지시문 양·생각 깊이를 한 모델 안에서 등급마다 다르게)을 하나씩 갈라 잰 공개 자료는 **우리 조사 범위에서** 찾지 못했다. 가까운 것은 Qwen3-30B-A3B·32B 의 일부 측정과, 같은 크기 모델이 "실행기에 따라" 크게 달라진다는 커뮤니티 보고뿐이다.
- 큰 모델 쪽 신호는 있다. 도구를 늘리면 큰 모델은 덜 떨어지거나 오르고, 많은 지시를 큰 모델은 더 잘 따르며, 생각 깊이는 큰 모델에서도 "최고가 늘 이기지 않는다". 같은 실험을 작은 모델과 큰 모델에 나란히 해 뒤집힘을 보인 연구는 찾지 못했다.

**출처 표시**
- 출처는 조사 서브에이전트 둘이 웹에서 찾은 것이다.
- **[원문]** 이 붙은 것만 원문을 읽었다. 표시가 없는 것은 초록·요약까지만 봤다("요약 페이지로 봄"·"(요약)"도 같다).
- 커뮤니티 보고(개인·이슈 글)는 동료 심사가 없고 표본이 작다.
- 이 조사가 "없다"고 한 것은 우리가 찾은 범위의 말이다. 놓친 자료가 있으면 알려 주면 고친다.

### 1-1. 도구 수
- MCPVerse(2025) [원문]: 도구를 늘리면 Qwen3-30B-A3B 33.3 → 22.8(−10.5), Qwen3-235B-A22B 47.9 → 42.3(−5.6), Claude-4-Sonnet 은 +3.2. **작은 모델일수록 도구가 많을 때 더 떨어진다**는 방향.
- Less is More(DATE 2025) [원문]: 1.5–8B 양자화 모델에서 그때그때 도구를 줄여 주면 성공률이 오르고 시간 최대 −70%.
- RAG-MCP(2025) [원문]: 후보 약 30개 밑이면 90% 넘게 맞히고 약 100개 넘으면 실패가 대부분(큰 상용 모델).
- Anthropic 도구 검색(2025-11) [원문]: 도구 검색을 켜면 Opus 4 49% → 74%. 도구 10개 미만이면 효과가 적다고 적음.
- **27B 밀집 모델에서 9–33개 범위를 단계로 바꿔 잰 것: 우리 조사 범위에서 못 찾음.**
### 1-2. 지시문·문맥 길이
- Context Rot(Chroma, 2025) [원문]: Qwen3-8B·32B·235B 포함 18개 모델 모두 입력이 길수록 떨어짐. 크기별 체계적 비교는 없음.
- IFScale(NeurIPS 2025) [원문]: 지시 10개는 모두 거의 다 따르고, 50개부터 작은 모델이 떨어짐. 큰 모델은 100개에서도 95% 넘게 따름. 앞쪽 지시를 더 잘 따르는 치우침.
- Context Length Alone Hurts(EMNLP Findings 2025): 필요한 정보를 다 찾아도 입력이 길면 13.9–85% 떨어짐. 군더더기를 공백으로 바꿔도 떨어짐 — **길이 자체의 효과**.
- 커뮤니티 재현(arcogine 이슈, 30B MoE, 도구 12개) [원문]: 지시문 약 40KB 에서 도구 호출 0/8, 1.5K자로 자르면 7/8, 짧은 지시문 8/8. **같은 크기의 무관한 글도 똑같이 실패** — 표본 8회.
- **27B 에서 지시 따르기·도구 쓰기를 지시문 길이로 잰 것: 우리 조사 범위에서 못 찾음.**
### 1-3. 생각 깊이
- Qwen3 기술 보고서 [원문]: 32B 는 도구 쓰기(BFCL)에서 생각 켬 70.3 · 끔 63.0, 긴 문맥(RULER)에서는 켬 91.0 · 끔 93.7 — **일에 따라 생각이 손해**. 30B-A3B 도 같은 방향.
- The Coupling Tax(2026): 출력 상한을 생각과 답이 나눠 쓰면 상한 2048 까지는 생각 끔이 같거나 나음(생각이 잘려 답 자리를 잃음). 생각·답 예산을 따로 주면 회복 — **우리 OverSearchQA 개발 점검에서 본 "가장 깊은 생각이 잘림"과 같은 꼴이다. 생각·답 예산을 따로 주는 칸(이 연구의 한 칸)이 바로 이것을 잰다**.
- The Danger of Overthinking(2025): 코딩 에이전트(SWE-bench, 모델 19개)에서 과잉 생각이 많을수록 성공률이 낮음.
- What Effort Level Should I Choose?(2026, 요약 페이지로 봄): 최고 깊이가 늘 이기지 않음, 모두가 푼 문제에서 최고 깊이는 비용 최대 42배. "낮은 깊이로 시작해 실패하면 올리기(laddering)"가 최고 고정과 같거나 나으면서 비용 15–42% 절감.
- 상용 큰 모델: GPT-5 종합 지수 high 68 · medium 67 · low 64(요약). Claude Code 문서 [원문]: 최신 모델의 기본 깊이는 medium, max 는 과잉 생각에 빠지기 쉬우니 시험 뒤 쓰라고 적음.
- **27B 에서 medium 같은 중간 깊이를 에이전트·코딩 과제로 잰 것: 우리 조사 범위에서 못 찾음**(켬·끔 두 갈래뿐).
### 1-4. 일·크기에 맞춰 설정을 다르게 두는 관행
- 제품: Cline 은 로컬 모델용 "compact prompt"(전체의 약 10%, MCP 도구 끔) [원문] · Aider 는 잘 모르는 모델에 가장 쉬운 편집 형식 · Claude Code 는 하위 에이전트마다 tools·disallowedTools·model·effort 를 따로, opusplan(계획 큰 모델, 실행 작은 모델) [원문] · OpenCode 는 모델별 다른 지시문. **모두 성능 수치는 없다.**
- 같은 모델, 다른 실행기: Qwen3.6-27B 가 SWE-bench Verified 에서 단순 실행기 67.8% 대 다른 실행기 85–90%(개인 보고) [원문] · Qwen3.6-35B-A3B 가 실행기 셋에서 0.62–0.66(커뮤니티) [원문]. **어느 구성 요소 때문인지(도구·지시문·생각)는 아무도 갈라 재지 않았다.**
- 경로 나누기 연구(RouteLLM·FrugalGPT·Route to Reason 등)는 4–8B 이거나 상용 API. 에이전트 걸음마다 깊이를 고르는 Ares(2026)는 "모든 걸음 low 면 크게 떨어진다".
### 1-5. 큰 모델에도 같은가
- 가장 좋은 생각 길이는 모델이 클수록 짧다(When More is Less, 1.5B–72B, 수학). 중간 크기는 생각 예산을 늘려도 정체(Qwen3 4B–32B 낱말 퍼즐).
- **같은 에이전트 과제를 27B 와 70B 이상에서 같은 등급으로 잰 연구: 우리 조사 범위에서 못 찾음.** 그래서 "우리 교훈이 큰 모델에서도 같다"는 말은 지금 할 수 없다.
### 1-6. 그래서 우리가 보탤 수 있는 것
1. 같은 27B 밀집 모델에서 도구 수·지시문 양·생각 깊이를 **하나씩 갈라** 등급마다 그 일로 잰 결과.
2. 지시문 **길이 효과와 내용 효과**를 가른 결과(같은 길이의 무관한 글과 비교) — 우리 조사 범위에서는 30B MoE 8회짜리 하나뿐.
3. 9B·27B·35B-A3B 를 나란히 재면 크기별 차이를 보일 수 있다(장비가 있을 때).
- 지금 우리 수치는 대부분 개발 탐색이다. 주장은 봉인 확증 뒤에만 한다.
